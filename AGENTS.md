## Project Overview

AsmrAiPlayer (AAP) is a Flutter-based ASMR.ONE client app (package name: `aaplay`, app ID: `com.aaplay`). It provides ASMR audio streaming with background playback, subtitle/lyric display, playlists, and caching. Licensed CC BY-NC-SA.

## Build & Development Commands

This project pins Flutter **3.27.0** via [`.fvmrc`](.fvmrc). Prefer `fvm flutter ...` to ensure the pinned SDK is used; substitute plain `flutter` only if you have it on PATH and matching the pinned version.

```bash
# Install dependencies
fvm flutter pub get

# Run code generation (freezed + json_serializable)
fvm dart run build_runner build --delete-conflicting-outputs

# Run the app (debug)
fvm flutter run

# Run all tests
fvm flutter test

# Run a single test file
fvm flutter test test/data/services/api_service_url_test.dart

# Static analysis (use this before commit). `withOpacity` has been fully
# migrated to `.withValues(alpha:)` (0 call-sites) — do not reintroduce it.
# A few pre-existing, UI-unrelated warnings remain (unused import/element in
# playback_controller / playback_context / recommendation_cache_manager /
# playlists_content, and a logger `printTime` deprecation) — don't add new ones.
fvm flutter analyze

# Analyze a single subtree (faster feedback while iterating)
fvm flutter analyze lib/widgets/sidebar/

# Build release APK
fvm flutter build apk --release

# Build iOS (no codesign)
fvm flutter build ios --no-codesign
```

**Local release signing (2026-09-28)**: `android/app/build.gradle` reads `android/key.properties` (`storeFile=../../upload-keystore.jks`, relative to `android/app/`), so a *local* release build needs the keystore at the **project root** `upload-keystore.jks` (alias `upload`, RSA-2048, 10000d) plus that properties file — both are gitignored (`.gitignore` carries `/upload-keystore.jks` **and** `**/android/app/upload-keystore.jks`). CI injects its own keystore at `android/app/upload-keystore.jks` (see `.github/workflows/build.yml`), so **locally-signed and CI-signed APKs are different signatures** and cannot upgrade each other — don't "fix" one by copying the other. Without `key.properties` the release build fails at `signingConfig`.

**Environment:** Dart SDK >=3.2.3 <4.0.0, Flutter 3.27.0 (FVM-pinned), Android min SDK 21 / target 33, Java 17.

**Renderer (Android):** Impeller is **disabled** via `io.flutter.embedding.android.EnableImpeller=false` in `android/app/src/main/AndroidManifest.xml` — Android builds use the Skia backend. Reason: real-device `Vulkan: ErrorDeviceLost` → `SIGSEGV in libvulkan.so::CmdEndRenderPass+4` long-session crashes on Xiaomi HyperOS 3 / Android 16 + Adreno (driver-level GPU fault, zero Dart frames). Don't re-enable Impeller without first upgrading the Flutter SDK (3.29+ has many Adreno fixes) and re-running a 30+ min real-device session — see `docs/todos/active/20260515-upgrade-flutter-sdk.md`. iOS continues to use Impeller (default and stable there).

## Architecture

Clean Architecture with three layers, using **Provider (ChangeNotifier)** for state management and **GetIt** for dependency injection.

### Layer Structure

- **`lib/core/`** - Platform services and infrastructure
  - `di/service_locator.dart` - GetIt DI container setup (entry point for all service registration)
  - `audio/` - Audio playback system: `IAudioPlayerService` interface + implementation, PlaybackEventHub (event bus pattern), state persistence, notification handling. **Lock-screen media notification invariants** (`notification/audio_notification_service.dart` + `audio_player_handler.dart`): the Android MediaStyle notification only renders a duration-backed seekbar when the `MediaItem` carries a non-null `duration`, but at `trackChange` time the source is usually not loaded yet — so `AudioNotificationService` listens to `playbackState` and re-pushes the `MediaItem` once the real duration is known. It also injects `ISubtitleService` and, since MediaStyle has no dedicated lyric line, **puts the current subtitle line in the `artist` row** (falls back to the real artist when no line is active); `MediaItem` is only re-pushed when track/duration/lyric actually changes (lyric is `distinct`-guarded) so artwork isn't refetched. The state stream only fires on play/pause/buffer transitions, so `AudioPlayerHandler` additionally re-emits `playbackState.copyWith(updatePosition:…)` from a **1s-throttled** `playbackProgress` subscription — `copyWith` auto-stamps `updateTime = now`, letting the lock-screen seekbar extrapolate between emissions. There is no native lock-screen *scrolling* lyric (vendor-only API, deliberately out of scope). **Playback-state persistence invariants** (`state/playback_state_manager.dart` + `storage/playback_state_repository.dart`, key `last_playback_state` in SharedPreferences): the persisted `PlaybackState` is **deliberately slim** — only `work / files / currentFile / playMode / position / timestamp`. `playlist` / `currentIndex` are **not persisted**: on restore, `restorePlaybackState()` rebuilds the context via the `PlaybackContext({work, files, currentFile, playMode})` factory which re-derives playlist/index from `files`+`currentFile` (`playback_context.dart:51-68`), so persisting them was dead, duplicated tree data. Old JSON carrying those keys still loads (json_serializable ignores unknown keys — no migration). Saves are **throttled to 20s** (debounce reset on every `playerStateStream` event); explicit flushes happen on `pause()`, playback completion, and best-effort in `dispose()`. `stop()` clears the persisted key so a stopped session isn't restored. **All persistence is serialized through a single `_persistChain` future + a `_persistSuppressed` tombstone**: `clearSavedState()` sets the flag synchronously and appends the `remove` to the chain tail, so a stop's `remove` can never be overtaken by an in-flight fire-and-forget `saveState()` (which would otherwise write a stopped session back); `saveState()` snapshots `context`/`positionMs` at call time and re-checks suppression inside the chain; `updateContext(non-null)` lifts suppression for new playback. Don't reintroduce direct `_stateRepository` writes that bypass the chain. **`PlaybackContext` playlist extension whitelist** (`playback_context.dart` `playlistAudioExtensions`): same-directory playlist construction only accepts `{mp3,wav,flac,m4a,aac,ogg,opus,wma,mp4a}` (not just mp3/wav — non-mp3 offline autoplay used to yield an empty playlist →「播放列表为空」). Video extensions are intentionally absent; don't add them. **Playable-file gate (2026-09-28)**: `PlaybackContext` now also owns the *only* playability API — `extensionOf` / `isPlayableAudioTitle` / `isSubtitleTitle` / `isVideoTitle` (+ `subtitleExtensions` / `videoExtensions`); `WorkFileItem` / `DetailViewModel` / `LocalCacheViewModel` no longer keep private copies. **Extension always beats the API `type`**: `type=='audio'` is never enough — a subtitle (`.vtt/.lrc/.srt/.txt`), a video or `album.json` sent as audio must be rejected, otherwise it gets a play button and reaches `setAudioSource`, mpv hangs loading the text file, and the next `_player.stop()` (previously untimed) interleaves with that in-flight load → `PlaybackController._setContextChain` deadlocks → every later play fails until restart. Local-cache rows render the play/translate buttons and `onTap` only for `LocalCacheViewModel.isPlayableEntry` (subtitles keep delete + preview only); `PlaylistBuilder.buildAudioSources` skips non-playable extensions as the last gate (`title==null` still builds a source — keep that); `_setPlaybackContext` runs `_player.stop()` under a **4s best-effort timeout** so one bad load can never wedge the chain. Covered by `test/core/audio/models/playback_context_playable_test.dart`, `test/presentation/viewmodels/detail_viewmodel_playable_test.dart`, `test/widgets/detail/work_file_item_play_button_test.dart` and `test/core/audio/cache/cache_dir_playability_test.dart` (per-file sweep of the real Downloads + `audio_cache` dirs with audio magic-byte sniffing).
  - `subtitle/` - Subtitle/lyric system: `ISubtitleService` interface, parsers (VTT etc.), subtitle loader with caching. **`SubtitleImportService` file/DB atomicity invariants** (`subtitle_import_service.dart`, paired with `UserSubtitleRepository` SQLite + files under app-docs `user_subtitles/<workId>/`): import must never leave the user's existing subtitle in a worse state on failure. The write sequence is: `picked.copy(tmpPath)` → if a file already sits at `destPath`, move it aside to `bakPath` (`backedUp=true`) → `tmp.rename(destPath)` (atomic on same FS) → `repository.upsert`. On success: delete the backup, then best-effort delete a *different-path* old file (ext change). On any failure: delete tmp, and if `backedUp` restore `bak→destPath`, then rethrow → `ImportResult.ioError`. Never delete the old file/DB row before the new import is fully confirmed (the old "delete-old → copy → upsert" order could destroy the user's subtitle, and `File.copy` is non-atomic). `removeImportedSubtitle` removes the **DB row first** behind a `dbRemoved` flag and only deletes the local file if the DB removal succeeded — a stale row pointing at a missing file makes the app think a subtitle still exists, whereas an orphan file is harmless. These ordering rules (consistency-critical DB op gated correctly relative to the file op; existing data preserved until success) must hold for any future change here. **Smart filename matching (2026-09-24)**: `SubtitleMatcher.findMatchingSubtitle` is a priority chain — ① exact full filename (base+ext / fullName+ext, case-insensitive) → ② normalized full name (`normalizeName`: lower + ext-strip + trim + full-width/collapsed whitespace + dash unify) → ③ stripped fuzzy (`stripNoise`: keep letters/digits/CJK/kana/hangul only, then equality → prefix → Levenshtein ≥ 0.6). `SubtitleLoader.findSubtitleFile` searches **same-directory siblings first, then the whole work tree** (`collectSubtitleFiles` preorder `.vtt/.lrc` only). **Playback resolution order** (`PlayerViewModel._loadSubtitleIfAvailable`): album.json recorded match (manual/history) → auto ①②③ (on hit, best-effort `recordSubtitleMatch(overwrite:false)`) → user import `user_subtitles` (deliberately **last**, user decision 2026-09-24) → clear. Manual pick = `showSubtitlePickDialog` from detail long-press on audio row **and** player subtitle menu「从专辑选择字幕」→ `recordSubtitleMatch(overwrite:true)` (overwrites). `collectAudioWithSubtitles` (batch download pairing) **stays same-directory only** (test-locked invariant); whole-tree fallback is playback-only. Matching/import still `.vtt/.lrc` only (preview 4-ext unchanged).
  - `audio/translation/` — bilingual「翻译+播放」(todo.txt 第一阶段.1, 2026-09-24): **true left/right ear channel isolation** (user overturned 2026-09-24「简化混播」decision): when enabled, main track hard-pans to `mainEar` and TTS to the opposite ear via mpv `af` lavfi `pan` (`ear_channel_router.dart`, Windows/Linux media_kit only — gated on `JustAudioPlatform.instance is JustAudioMediaKit`); Android/iOS native just_audio has no pan API so those platforms **no-op degrade** to the volume-emphasis mix (`TranslationMixState` primary 1.0 / secondary 0.7 still balances loudness; `setVolume` stays clamped). Implementation: vendored fork `third_party/just_audio_media_kit` (pubspec `dependency_overrides` path — upstream upgrades need manual fork sync) adds `MediaKitPlayer.setAudioFilter` + a role registry; `EarChannelRouter.expectMainPlayer()`/`expectTtsPlayer()` must be called **before** each `AudioPlayer()` construction (only two call-sites: `AudioPlayerService` main, `TranslationSessionController` TTS) — role queue assumes **main platform init first** (holds: translation only starts after main playback; `JustAudioMediaKit.ensureInitialized()` stays before `setupServiceLocator()`). Filter = `lavfi=[aformat=channel_layouts=stereo,pan=stereo|c0=0.5*c0+0.5*c1|c1=0]` (left) / opposite for right (mono downmix into one ear, other side silent); `apply(null)` clears `af` when session disabled/`endSession`. Do **not** use mpv `balance` (maps L to both speakers). Route is pushed from `TranslationSessionController._applyVolumes` → `_applyEarRouting` (`enabled ? mainEar : null`) and re-applied after TTS player setVolume; failures only `AppLogger.warning` (never block playback; fork keeps best-effort `.ignore()` so bad `af` cannot fail init). `disposePlayer` keeps `id→role` so stop→play re-init restores role+filter. Detection chain `EarSideDetector`: persisted `EarMarkRepository` mark (`fileKey` → left/right in prefs `translation_ear_marks`) → filename regex (`left`/`right` with `[_-]` treated as word boundaries, case-insensitive, both-sides → null) → local stereo `.wav` RMS (`wav_stereo_rms.dart`, pure-Dart PCM16/float32, dominant side relative 5% threshold, ~200k-frame sampling) → else `ear_side_prompt_dialog`. `TranslationSessionController` is a GetIt singleton ChangeNotifier: holds the second player, an **epoch** that invalidates in-flight Fish TTS, and subscribes `PlaybackEventHub` (playbackState / trackChange / contextChange / playbackCleared) + `ISubtitleService.currentSubtitleStream`. Toggle off must restore main volume to 1.0 and mute the translation track; swap direction flips `mainEar` **and** exchanges the primary(1.0)/secondary(default 0.7) emphasis volumes together. TTS text source = **current subtitle line only** (existing 汉化字幕 premise); no subtitle → SnackBar, never a title read-aloud. Normal play never auto-starts a session — only `TranslationPlayFlow.prepareSession` (list「翻译+播放」entries) or the player-page toggle. **Fish Audio TTS** (`fish_tts_service.dart`): `POST https://api.fish.audio/v1/tts`, Bearer key from `flutter_secure_storage` (never plaintext prefs), body `{text, reference_id?, format:'mp3'}`, model `s2.1-pro|s2-pro|s1|s2.1-pro-free`; disk cache key = `sha256(model\0ref\0text)` under `getApplicationSupportDirectory()/fish_tts_cache`; 401/403 → `FishTtsError.unauthorized`; **Dio carries `ProxyConfig.apply`** (settings injected in DI — TTS follows the in-app proxy like every other Dio client). `IAudioPlayerService.setVolume` was added solely for the mix emphasis — keep it clamped. Voice IDs are non-sensitive → plain SharedPreferences (API key stays in secure storage). Do not add role/speaker auto-assignment UI yet — structure is reserved only. **Translation volume auto/manual (2026-09-28)**: `_applyVolumes` now routes every decision through `TranslationVolumePolicy.compute` (`translation_volume_policy.dart`): `translationAutoVolume` (pref `translation_auto_volume`, **default true**) + session on + **both** tracks' RMS measured ⇒ align the louder side down (`clamp(tts/main,0.1,1)` / `clamp(main/tts,0.1,1)`, floor `minVolume=0.1`; `usable()` rejects null/non-finite/`<1e-4`); every other combination returns the old emphasis (`state.mainVolume/state.translationVolume`) unchanged, so auto-off / online-stream / flac reproduces today's behavior exactly.   **Floating lyric invariants** (Android `LyricOverlayService.kt` + `lyric_overlay.xml`): the overlay is **pass-through by default** — `FLAG_NOT_TOUCHABLE` **and** `LayoutParams.alpha = 0.8` (`PASS_THROUGH_ALPHA`). The alpha is load-bearing, not cosmetic: Android 12+ `getMaximumObscuringOpacityForTouch()` (default 0.8) means an opaque `TYPE_APPLICATION_OVERLAY` still eats the underlying app's touches even with `FLAG_NOT_TOUCHABLE` — don't raise it above 0.8 in pass-through mode. New atoms get a "three-variant" widget test (`test/widgets/common/atom_three_variant_test.dart` pattern). `docs/ui-design-spec.md` is **v4.0**, rewritten to this real two-axis system + the atom-reuse matrix (the reference-image mockup is the visual basis; the old "purple `fromSeed`" spec is gone).
  - `cache/` - RecommendationCacheManager; `CacheCoordinator` (unified clean/clear API); `CacheLifecycleManager` (a `WidgetsBindingObserver` singleton — startup cleanup is deferred to `addPostFrameCallback` so the stat-heavy scan doesn't fight first-frame render; `resumed` triggers immediate cleanup; both gated by a 6h throttle + reentrancy flag). **`AudioCacheManager.cleanCache()` LRU invariants**: it must collect `(file, stat)` once via `await file.stat()` and NEVER call `statSync()` in a sort comparator (O(N log N) blocking FS calls froze frames). Eviction is true LRU: delete expired (>30d) first, then sort survivors by `stat.modified` ascending and delete oldest-first until `totalSize <= _maxCacheSize` (1GB), decrementing `totalSize` per delete. A delete failure (file in use) only skips that file — it does NOT abort the sweep. **An expired file whose delete fails must be added back into the `live` set**, not dropped: otherwise it still occupies disk but escapes capacity accounting, and actual usage can blow far past the limit. `modified` is the LRU proxy (atime is unreliable cross-platform; `LockCachingAudioSource` writes as it downloads so modified ≈ last-cached). It keeps an in-memory cache (`_cached`/`_loaded`) so `AuthInterceptor` does zero storage/JSON work per request after the first load; `getAuthData()` dedupes concurrent first-loads via `_loadFuture ??= _loadAndMigrate()` (no `await` between null-check and assign). One-time migration of legacy plaintext `auth_data`: only `prefs.remove` **after** a successful secure write — migrate-fail keeps plaintext and does NOT log the user out. **Defensive degrade**: any secure-storage read/write failure (Keystore broken on some OEM ROMs) falls back to prefs rather than crashing or logging out — worst case it degrades to the old plaintext behavior. All secure/prefs *mutations* (legacy migrate, save, clear) run through a single `_serialize`/`_writeLock` chain so issue-order == persist-order — without this, an in-flight legacy-migrate `_secure.write(oldToken)` could complete after a concurrent `saveAuthData(newToken)` and resurrect the old token in secure storage. The `if (_loaded) return _cached;` guards before each cache commit protect the authoritative in-memory state when a save/clear lands during a load. ### API

Two Dio clients, both pointed at the user-selected node:
- `ApiService` — content endpoints (`/works`, `/tracks/{id}`, `/search/{keyword}`, `/review`, `/recommender/*`, `/playlist/*`, `/tags/`, `/circles/`, `/vas/`, `/workInfo/{id}`). Auth header added by `AuthInterceptor`. **`searchWorks` must build its URL via `ApiService.buildSearchUri` (`Uri.replace(pathSegments:[...])` + `_dio.getUri`), not string-concatenated `'/search/$keyword'`**: some tag names contain `/` (e.g. `巨乳/爆乳`); a concatenated `%2F` gets decoded back to `/` inside Dio's `Uri.parse`, the server splits the path → 404. `buildSearchUri` is `static` + unit-tested precisely so the keyword stays one path segment. Apply the same pattern to any future endpoint that puts user/tag text in the **path** (query params are unaffected).
- `AuthService` — `/auth/me` (login) and `/auth/reg` (register). Owns its own Dio instance, no auth interceptor.

Both services subscribe to `AppSettingsService` and rotate `dio.options.baseUrl` when the user switches nodes. Available nodes (defined in `AppSettingsService.serverOptions`):
- `https://api.asmr.one/api` (主站, default)
- `https://api.asmr-100.com/api` / `-200` / `-300` (mirror nodes)

When adding a new HTTP-touching service, follow the `_onSettingsChanged` pattern in `ApiService`/`AuthService` — don't hardcode the host. **Deliberate exception:** `UpdateService` is a third Dio client hardwired to `https://api.github.com` and intentionally does *not* follow this pattern — GitHub is unrelated to asmr node switching. Only the asmr-content/auth services rotate with the selected node.

**Proxy (transport-level, orthogonal to node rotation):** every Dio client also calls `ProxyConfig.apply(dio, settings)` at construction (`core/network/proxy_config.dart`). It does **not** use a settings listener — `HttpClient.findProxy` is wired via `IOHttpClientAdapter.createHttpClient` to a closure that reads `proxyEnabled`/`proxyUrl` per connection, so changes apply on the next request. `UpdateService` receives `AppSettingsService` **only** for this (its baseUrl stays hardwired); `DownloadService`'s `settings` param is optional so unit tests keep a bare `Dio()`. UI lives in Settings → 网络 (`ProxyAddressDialog` validates through `ProxyConfig.normalize` before persisting).

### Error-prompt UX (connection vs. login state)

A list-page error must communicate the **right recovery action**, not just "出错了 + 重试". This invariant spans four layers — keep them consistent when adding a new paginated screen:

1. **Data**: `NetworkException.userMessage` centralizes the copy (VPN hint for connection/timeout, "请先登录" for 401/403). Don't surface `e.toString()` to users.
2. **ViewModel**: list ViewModels (`FavoritesViewModel`, `RecommendViewModel`) expose `bool isLoginError` alongside `String? error`. Set it `true` in the not-logged-in early return **and** when a caught `NetworkException.isAuthError` is true; reset to `false` before each load and on non-auth errors. The `catch` block routes through `NetworkException.userMessage`.
3. **Widget**: `EnhancedWorkGridView` and the legacy `WorkGridView` take `isLoginError` + `onLogin` (both optional, defaulting to retry behavior so other screens are unaffected). When `isLoginError && onLogin != null` they render a **"去登录" button instead of "重试"** (retrying a not-logged-in request is pointless). `GridError` owns the actual branching.
4. **Screen**: content screens pass `isLoginError: vm.isLoginError` and an `onLogin` that opens `LoginDialog` on the **root navigator** (`useRootNavigator: true`), `await`s it, and reloads the list if `context.read<AuthViewModel>().isLoggedIn` afterward. The standalone `FavoritesScreen` (sidebar route, still on legacy `WorkGridView`) is wired the same way for parity. `RecommendContent`'s `Selector` record must include `isLoginError` so the grid rebuilds when it flips.
